# ② Style プロンプト生成（チャット主導 / 散文版）

## 入力
`work/features_<日付>.json`（①の出力）

## 出力
`work/style_prose_<日付>.md` — **Styles** と **Exclude Styles** の2ブロック（現行 Suno の Style欄／除外欄に対応）

## Styles（Positive Prompt）の作成ルール
- 言語=英語、**1000字以下（スペース含む）**。入り切らなければ全体を簡略化して短縮
- **固有名詞なし**（アーティスト名・曲名・レーベル名を書かない）
- 情景豊かな「散文」で、以下の要素を順に織り込む:
  1. **核となるモチーフ／フック** — 冒頭や核のメロディ／シンセフレーズを具体的に描写
  2. **ジャンルとムードの融合** — 単一ジャンルでなく、複数ジャンル／ムードがどう混ざるかを質感付きで
  3. **ボーカルの質感と感情** — 性別・年代に加え、声質・感情の込め方・空気感
  4. **プロダクションと音響** — レイヤー感、音の質感、リバーブ／空間処理
  5. **リズムとグルーヴ** — キック／ベースが推進力と雰囲気をどう作るか
  6. **曲の展開とダイナミクス** — 始まり方、盛り上がり、静まり、感情の起伏
  7. **独自の要素（Twist）** — その曲をユニークにするひねり／特徴的なフレーズ
  8. **全体像とループ性** — 全要素がどう噛み合い、リプレイ性／中毒性につながるか
- ①の実データ（4/4・調性・BPM帯・制作スタイル）と矛盾しないこと
- **このプロジェクトの棚（作業用BGM）に合わせる**: 盛り上げすぎない。"nothing sharp or forward",
  "sits back in the mix", "lifts only a little" のように控えめさを明示。参照例文が
  trance/euphoric 寄りでも、語彙は「暖かい・夜・低刺激」に振る

## Exclude Styles（Negative Prompt）の作成ルール
- 言語=英語、**Styles の20〜40%の文字数**、**カンマ区切りリスト**
- 除外したい要素を**そのまま**書く（"Exclude ..." や "No ..." を付けない）
- 観点: ①相反するムード ②避けたいジャンル・展開（過度に商業的／攻撃的）
  ③避けたいプロダクション（人工的・過剰処理）④陳腐な要素（ありきたりなリズム／進行）

## 案は基本1つ（メイン）＋振り幅メモ
1000字散文はテイクの解像度が高いので、まずメインを1つ完成させる。
「案A=ジャズ寄り」「案C=シネマティック」に振る場合の**差し替え行**を末尾にメモしておく
（融合行と Twist を差し替える形）。

## ④での使い方
Styles を Style欄、Exclude Styles を除外欄へ。歌詞欄は ③ の検証済み歌詞。
固定アーティスト名（`branding.md`）と Persona ボーカルは毎回同じものを使う。
